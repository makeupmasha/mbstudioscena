## Как устроен пакет

| Часть | Технология и назначение |
| --- | --- |
| Веб-приложение | Python 3.12, Tornado, серверный HTML, CSS и JavaScript |
| Сборка | `Dockerfile.vercel` и `requirements-web.txt` |
| Исходный код | GitHub; обновления публикуются через связанный проект Vercel |
| База | Turso / libSQL: настройки, услуги, заявки, заказы и сведения о файлах |
| Закрытые файлы | Приватный Vercel Blob: оригиналы фотографий и временные файлы |
| Публичные изображения | Публичный Vercel Blob: подготовленные версии опубликованных фотографий |
| Демонстрационные изображения | Файлы репозитория; сборка подготавливает статические веб-ресурсы |
| Email | Resend с собственным ключом и подтверждённым отправителем |
| Telegram | Собственный бот и получатели, настроенные владельцем |

**Код и данные живут отдельно.** Изменение услуги или фотографии в кабинете сохраняется в базе и хранилищах. Оно не создаёт коммит в GitHub. Копирование репозитория создаёт основу новой установки; существующие облачные данные таким способом не переносятся.

Первый запуск на пустой базе создаёт демонстрационное содержание и собственные идентификаторы установки. Повторный запуск сохраняет изменения владельца. Инициализация общей базы защищена от одновременного запуска нескольких экземпляров приложения.

## Быстрый локальный запуск

Нужны **Git и Python 3.12**. Выполняйте команды из папки репозитория.

```bash
git clone https://github.com/makeupmasha/mbstudioscena.git
cd mbstudioscena
python -m venv .venv
```

Установите зависимости, соберите ресурсы и запустите превью.

**Windows / PowerShell:**

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-web.txt
.\.venv\Scripts\python.exe deploy/build_web_assets.py
.\.venv\Scripts\python.exe deploy/start_demo.py
```

**macOS / Linux:**

```bash
.venv/bin/python -m pip install -r requirements-web.txt
.venv/bin/python deploy/build_web_assets.py
.venv/bin/python deploy/start_demo.py
```

Откройте [http://localhost:8877/ru/](http://localhost:8877/ru/). Кабинет доступен через навигацию сайта; случайный локальный пароль находится в `data/demo-password.txt`.

- Локальная база: `data/demo.db`.
- Данные и пароль исключены из Git.
- `start_demo.py` очищает облачную конфигурацию окружения и запускает изолированное превью без Resend.
- Превью работает, пока запущен процесс. Остановка: `Ctrl+C`.
- Если порт занят, задайте другой `PORT` перед запуском, например `$env:PORT="8878"` в PowerShell.

Для опубликованного сайта используется `deploy/start_web.py`; локальный `start_demo.py` предназначен для ознакомления с пакетом.

## Установка для нового владельца

1. **Создать собственный репозиторий.** Скопировать исходники в аккаунт владельца. Не добавлять действующую базу, пароли, резервные копии и личные загрузки.
2. **Создать отдельный проект Vercel.** Подключить новый репозиторий и настроить контейнерную сборку через `Dockerfile.vercel`. В образе уже заданы подготовка ресурсов и команда запуска.
3. **Создать хранилища владельца.** Пустую базу Turso, один публичный и один приватный Vercel Blob. Использовать их собственные адреса и токены.
4. **Задать переменные окружения.** Список ниже и в [.env.example](.env.example). Настройки в Vercel должны быть доступны нужному окружению развёртывания.
5. **Опубликовать и проверить.** Открыть сайт, войти в кабинет, изменить услугу, загрузить фотографию и проверить сохранение после повторного запуска.
6. **Подключить домен.** Настроить DNS по значениям, которые показывает именно новый проект Vercel, дождаться HTTPS и согласовать публичный адрес в окружении и настройках сайта.
7. **Заполнить реальную анкету.** Заменить демонстрационные материалы, проверить языковые версии, услуги, цены и контакты. Для рабочей установки задать `SCENA_DEMO_SITE=0`; индексацию включить отдельно в кабинете.
8. **Подключить уведомления.** Настроить собственные Resend и Telegram, проверить фактическую доставку согласованных тестовых сообщений.

Для независимых заказчиков рекомендуется отдельное владение репозиторием, проектом и хранилищами. Если несколько проектов находятся в одной команде Vercel, они расходуют её общий бюджет ресурсов.

### Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `SCENA_PUBLIC_BASE_URL` | HTTPS-адрес установки без пути, например `https://studio.example` |
| `SCENA_ADMIN_PASSWORD` | Собственный пароль кабинета; минимум 8 символов, рекомендуется длинный случайный пароль |
| `SCENA_TURSO_TURSO_DATABASE_URL` | Адрес базы Turso |
| `SCENA_TURSO_TURSO_AUTH_TOKEN` | Токен доступа к этой базе |
| `SCENA_PUBLIC_BLOB_READ_WRITE_TOKEN` | Токен публичного Blob |
| `SCENA_PRIVATE_BLOB_READ_WRITE_TOKEN` | Токен приватного Blob |
| `SCENA_DEMO_SITE` | `1` — демонстрационный режим; `0` — после подготовки реальной установки |
| `SCENA_EMAIL_FROM` | Необязательно: подтверждённый адрес отправителя |
| `RESEND_API_KEY` | Необязательно: ключ Resend для доставки email |
| `SCENA_MAIL_ROOT_DOMAIN` | Необязательно: корневой почтовый домен для отдельно настроенной схемы поддоменов |

Первые шесть переменных обязательны для облачного запуска. При неполной конфигурации запуск останавливается. `.env.example` — образец имён; действующие значения нужно внести в окружение Vercel, а не в Git. Сам файл `.env` эти команды автоматически не загружают.

### Обновления и сохранность

- Коммиты в production-ветку связанного репозитория могут запускать автоматическое развёртывание Vercel. Проверяйте выбранную ветку и результат сборки.
- Перед изменениями структуры данных создавайте резервную копию через кабинет.
- Проверка переноса включает восстановление копии в отдельной тестовой установке.
- Откат кода не возвращает прежнее состояние базы. База и Blob требуют собственного плана резервирования.
- Для тестовых развёртываний используйте отдельные данные, чтобы проверки не меняли рабочую установку.

## Фотографии и бюджет ресурсов

Файлы фотографий занимают **Blob**, а записи об этих файлах — **Turso**. Объём базы данных не прибавляется к месту для фотографий.

Одна фотография может занимать место как оригинал, публичная WebP-версия и временная копия загрузки. Кроме хранения расходуются передача изображений посетителям, операции с файлами и серверные вычисления.

**Ограничение стартового пакета:** в механизме временных файлов срок доступа составляет 12 часов; сам срок не удаляет объект из Blob. Перед обещанием фиксированной вместимости клиенту необходимо внедрить и проверить очистку временных файлов. Повторные загрузки и дополнительные копии учитываются в общем объёме.

Лимиты, тарифы и условия использования проверяются при каждой установке: [Vercel Hobby](https://vercel.com/docs/plans/hobby), [Vercel Blob](https://vercel.com/docs/vercel-blob/usage-and-pricing), [Turso](https://turso.tech/pricing). Бесплатность конкретного коммерческого размещения и постоянный объём ресурсов не входят в гарантию пакета; Hobby предназначен для личного некоммерческого использования.

## Проверка перед передачей

- [ ] Главная, услуги, запись, портфолио и визитка открываются на нужном домене.
- [ ] Кабинет защищён паролем; выход и повторный вход работают.
- [ ] Изменение услуги сохраняется после перезапуска.
- [ ] Фотография сохраняется, отображается и доступна владельцу в оригинале.
- [ ] Тестовая заявка появляется в кабинете; её статус изменяется.
- [ ] Email и Telegram доставляют сообщения нужным получателям, если подключены.
- [ ] Резервная копия восстанавливается в отдельной тестовой установке.
- [ ] На телефоне проверены публичные страницы и основные действия кабинета.
- [ ] Указаны реальные контакты, согласованы языковые версии и индексация.
- [ ] Проверены использование хранилищ и условия выбранных тарифов.

В `tests/` есть проверки бизнес-логики, интерфейса, переноса данных и первого запуска. Например, из корня проекта с установленными веб-зависимостями:

```bash
python -m unittest discover -s tests -p test_independent_installation.py
python -m unittest discover -s tests -p test_bootstrap_concurrency.py
```

Используйте Python созданного виртуального окружения. Эти проверки используют временные локальные базы и не заменяют проверку новой облачной установки.
